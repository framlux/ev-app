# EV App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record Tesla Model Y telemetry continuously into self-hosted Postgres and present drives, charges and battery health through a SvelteKit site behind Pocket-ID SSO, running on the existing k3s cluster.

**Architecture:** The car streams over mTLS to an upstream `fleet-telemetry` receiver, which publishes decoded JSON to Mosquitto with `reliable_ack` and QoS 1. A TypeScript ingest worker consumes that, writes an immutable `raw_message` tape plus normalised `sample` rows, and incrementally segments drives/charges/idles. A SvelteKit app serves both the UI and a versioned read API over the derived tables. All vendor-specific code sits behind a single `VehicleAdapter` interface so Rivian is additive later.

**Tech Stack:** TypeScript (ESM, Node 22), pnpm workspaces, vitest, PostgreSQL 17 via CloudNativePG, node-pg-migrate, mqtt.js, SvelteKit 2 / Svelte 5 with `adapter-node`, openid-client v6, prom-client, MapLibre GL, Kustomize + ArgoCD, GitHub Actions → ghcr.io.

**Spec:** `docs/superpowers/specs/2026-09-04-ev-app-design.md`

## Global Constraints

- **Read-only.** OAuth scopes are exactly `openid`, `vehicle_device_data`, `vehicle_location`. Never request `vehicle_cmds` or `vehicle_charging_cmds`.
- **Never poll `vehicle_data` on a schedule.** Metered at $1/500 requests; wakes at $1/50. Fleet API calls are for vehicle list, `key_paired` status and telemetry config only.
- **Namespace:** `ev`. One namespace for the whole application, per the stack repo's convention.
- **Hostnames:** `ev.framlux.io` (web + API + Tesla public key), `ev-telemetry.framlux.io` (vehicle stream).
- **Images:** `ghcr.io/framlux/ev-web`, `ghcr.io/framlux/ev-ingest`, `ghcr.io/framlux/ev-migrator`. Tags pinned in the kustomization `images:` block, never `latest`.
- **Manifests live in the `framlux/stack` repo** at `clusters/prod/apps/ev/base/`, not in this repo. Adding an app is the four-step procedure in that repo's CLAUDE.md: base dir, `ev-app.yaml`, root kustomization entry, push to `main`.
- **Task tracking in the `stack` repo uses `bd` (beads)**, not markdown TODOs. This repo has no such requirement.
- **CNPG conventions:** `storageClass: data-disk`, `priorityClassName: data-tier`, image `ghcr.io/cloudnative-pg/postgresql:17.6`, requests 256Mi/250m, limits 512Mi/1.
- **Every `sample` column except `vehicle_id` and `ts` is nullable.** Vendors disagree about what they expose and the R2 is unverified.
- **All secrets are SealedSecrets.** Never commit a plaintext Secret to the stack repo.
- **Node 22, ESM throughout.** `"type": "module"` in every package.

## Plan corrections found during implementation

These are defects in this document, discovered by building it. Read them before executing
any remaining task — several tasks below still contain the uncorrected text.

**1. Task 10's segmenter code contained a critical bug (fixed in `de29fa8`).**
The charge branch never checked whether the car was moving. A car that unplugs and drives
away while `chargeState` is still `'stopped'` — the normal case, since `'disconnected'`
often arrives late or not at all — stays inside the charge branch until the resume window
expires. Its samples emit no events at all: the drive's first minutes are silently
swallowed and belong to no session. The fix adds a motion exit to the charge branch.
**The repository is now authoritative for the segmenter, not this plan.** Read
`packages/core/src/engine/segmenter.ts`.

**2. Task 10's `isMoving` coerced null speed to zero (fixed in `de29fa8`).**
`(sample.speedKph ?? 0) > threshold` treats a sample that merely omits speed as stationary,
splitting one continuous drive into two. Replaced with a three-valued `motionOf()` —
moving, stationary, or unknown — where unknown neither starts nor clears the parked clock
and never opens a drive. This is the direct consequence of the spec's own rule that every
field is nullable, and the original code violated it.

**3. Task 10 closed a paused charge at the wrong timestamp (fixed in `de29fa8`).**
The session was closed at whichever sample happened to cross the resume window, not at the
time charging actually stopped, inflating charge duration by an arbitrary amount bounded
only by the sample gap.

**4. Task 3 Step 2 cannot be followed as written.** SvelteKit 2.63 with `sv` 0.17 emits no
`svelte.config.js` at all — Kit configuration now lives in the `sveltekit()` plugin options
inside `apps/web/vite.config.ts`. Configure `adapter({ out: 'build' })` there. Any later Kit
config (aliases, CSP, prerender) goes in `vite.config.ts`, not a `svelte.config.js`.
Relatedly, `pnpm create svelte@latest` is retired; use
`pnpm dlx sv@latest create apps/web --template minimal --types ts --no-add-ons`.

**5. Task 7's `ev-mqtt-auth` needs TWO keys, not one.** The plan seals only `passwd`, the
hashed file Mosquitto reads. `ev-ingest` authenticates as a *client* and needs the
plaintext, so the same Secret must also carry `MQTT_PASSWORD`. As originally written,
`ev-ingest` would receive an env var containing a bcrypt hash and fail to authenticate.

**6. Task 7's `tesla/fleet-telemetry:v0.7.4` never existed.** Upstream went v0.7.2 → v0.8.0.
Current release is v0.9.4. Config-schema changes between v0.7.x and v0.9.x are plausible,
so validate the config against the pinned version before pointing the car at it.

**7. Task 7 produces a Secret the plan never names: `ev-telemetry-config`.** Because the
MQTT password is inline in `config.json`, the telemetry config is a SealedSecret, not the
ConfigMap spec §3.2 calls it. Two traps documented in the stack repo's `SECRETS.md`: the
`client_id` must differ from `ev-ingest`'s (MQTT permits one connection per client id, so
sharing it makes publisher and subscriber evict each other in a loop), and `topic_base`
must agree with `MQTT_TOPIC` or ingest connects cleanly and receives nothing.

**8. Task 12 needs configuration the plan never specifies.** `Pipeline` is constructed with
a vehicle identity and `MetricsOptions.usableCapacityKwh`; neither had a config source.
Both are now keys in the `ev-config` ConfigMap.

**9. Task 8's migration tests can never run locally without Docker.** They are gated on
`PGHOST`. `.github/workflows/test.yml` now runs a `postgres:17-alpine` service and the test
file throws at load time when `CI` is set but `PGHOST` is not, so the skip cannot silently
return. CI is their first real execution — treat the migrations as unverified until it runs.

**10. `apps/web` legitimately depends on `@ev/core` for types**, which makes the engine
reachable through the barrel. `apps/web/test/boundaries.test.ts` enforces the ban on engine
imports; keep it passing rather than relying on the prose rule in the File Structure section.

**Boundary rules that matter:**
- `packages/core` has **no I/O and no dependencies on `pg`, `mqtt` or SvelteKit.** It is pure functions over types. This is what makes the engine testable and what keeps a later extraction to Go or C# cheap.
- `packages/tesla` may not import `packages/db`. Adapters produce values; they do not persist.
- `apps/web` may not import `packages/core/engine`. The web reads derived tables.

- [ ] **Step 3: Write the model**

`packages/core/src/model.ts`:

```ts
export type Vendor = 'tesla' | 'rivian'

/** Whether the car's computer is reachable. Not whether it is moving. */
export type PowerState = 'online' | 'asleep' | 'offline'

export type ChargeState =
  | 'disconnected'
  | 'connected'
  | 'charging'
  | 'complete'
  | 'stopped'

export type RawSource = 'telemetry' | 'fleet_api' | 'graphql_ws'

export interface RawMessage {
  vehicleId: string
  vendor: Vendor
  receivedAt: Date
  source: RawSource
  payload: unknown
}

/**
 * The canonical vehicle observation. Vendor-neutral by construction.
 *
 * Every field but vehicleId and ts is nullable: vendors disagree about what
 * they expose, and a missing field must be distinguishable from a zero.
 * Rivian, for instance, does not expose battery temperature at all.
 */
export interface VehicleSample {
  vehicleId: string
  ts: Date
  socPct: number | null
  rangeKm: number | null
  odometerKm: number | null
  lat: number | null
  lon: number | null
  speedKph: number | null
  powerState: PowerState | null
  chargeState: ChargeState | null
  chargePowerKw: number | null
  chargeEnergyAddedKwh: number | null
  insideTempC: number | null
  outsideTempC: number | null
  locked: boolean | null
  doorsOpen: boolean | null
  tpms: Record<string, number> | null
}

export type SessionKind = 'drive' | 'charge' | 'idle'

export interface Session {
  id: string
  vehicleId: string
  kind: SessionKind
  startedAt: Date
  endedAt: Date | null
  startOdometerKm: number | null
  endOdometerKm: number | null
  startSocPct: number | null
  endSocPct: number | null
  energyKwh: number | null
  distanceKm: number | null
  efficiencyWhPerKm: number | null
  avgSpeedKph: number | null
  maxChargePowerKw: number | null
  startLat: number | null
  startLon: number | null
  endLat: number | null
  endLon: number | null
  isOpen: boolean
}

export interface SessionPoint {
  sessionId: string
  ts: Date
  lat: number | null
  lon: number | null
  socPct: number | null
  speedKph: number | null
  powerKw: number | null
}

const NULL_SAMPLE: Omit<VehicleSample, 'vehicleId' | 'ts'> = {
  socPct: null,
  rangeKm: null,
  odometerKm: null,
  lat: null,
  lon: null,
  speedKph: null,
  powerState: null,
  chargeState: null,
  chargePowerKw: null,
  chargeEnergyAddedKwh: null,
  insideTempC: null,
  outsideTempC: null,
  locked: null,
  doorsOpen: null,
  tpms: null,
}

/**
 * Build a sample with explicit nulls for everything unspecified.
 * Used by adapters and by every test fixture in this repo.
 */
export function makeSample(
  partial: Pick<VehicleSample, 'vehicleId' | 'ts'> & Partial<VehicleSample>,
): VehicleSample {
  return { ...NULL_SAMPLE, ...partial }
}
```

- [ ] **Step 4: Write the adapter interface**

`packages/core/src/adapter.ts`:

```ts
import type { RawMessage, Vendor, VehicleSample } from './model.js'

/**
 * The single vendor seam. Nothing downstream of normalise() knows which
 * make of car produced a sample. Adding Rivian means adding one
 * implementation of this and changing nothing else.
 */
export interface VehicleAdapter {
  readonly vendor: Vendor
  /** Begin delivering raw messages to the sink. Resolves once connected. */
  start(sink: (m: RawMessage) => Promise<void>): Promise<void>
  /** Stop cleanly, flushing anything in flight. */
  stop(): Promise<void>
  /** Pure. One raw message may yield zero, one or many samples. */
  normalise(raw: RawMessage): VehicleSample[]
}
```

```yaml
  name: ev-pg

    argocd.argoproj.io/sync-wave: "0"
  labels:
    app.kubernetes.io/name: ev-pg
    app.kubernetes.io/part-of: ev

spec:
  instances: 1
  imageName: ghcr.io/cloudnative-pg/postgresql:17.6
  primaryUpdateStrategy: unsupervised

  storage:
    storageClass: data-disk
    size: 20Gi

  priorityClassName: data-tier
  resources:
    requests:
      memory: "256Mi"
      cpu: "250m"
    limits:
      memory: "512Mi"
      cpu: "1"

  postgresql:
    parameters:
      max_connections: "100"
      shared_buffers: 128MB

  bootstrap:
    initdb:
      database: ev
      owner: ev_app

  # Backups are configured from the start, not retrofitted. Unlike crm-pg, this
  # data cannot be re-fetched from anywhere: both Tesla and Rivian serve live
  # state only and keep no history for you. Losing this volume loses the archive
  # permanently. PostgresBackupStale in observability/base/prometheus/alerts.yaml
  # covers every namespace except crm, so an unbacked cluster here would also
  # page within 26 hours - correctly.
  backup:
    barmanObjectStore:
      destinationPath: s3://framlux-backups/cnpg/ev
      # Explicit from the start. A serverName bump or a re-created data directory
      # must be accompanied in the SAME change by an on-demand Backup or a
      # recreated ScheduledBackup, because immediate: true does not fire on a
      # ScheduledBackup that already exists.
      serverName: ev-20260904
      endpointURL: https://s3.us-west-004.backblazeb2.com
      s3Credentials:
        accessKeyId:
          name: backup-b2-credentials
          key: B2_KEY_ID
        secretAccessKey:
          name: backup-b2-credentials
          key: B2_APP_KEY
      wal:
        compression: gzip
      data:
        compression: gzip
    retentionPolicy: "30d"

  monitoring:
    enablePodMonitor: false
```

```yaml
apiVersion: postgresql.cnpg.io/v1
kind: ScheduledBackup
metadata:
  name: ev-pg-daily
  annotations:
    argocd.argoproj.io/sync-wave: "1"
  labels:
    app.kubernetes.io/part-of: ev
spec:
  # Six-field cron including seconds, which is CNPG's format and not crontab's.
  # 05:00 staggers behind vord-fleet (02:00), corp-sso (03:00) and analytics
  # (04:00) so the clusters do not compete for the node's disk and uplink.
  schedule: "0 0 5 * * *"
  backupOwnerReference: self
  # Takes a base backup immediately rather than waiting for the first 05:00.
  # Without it there is a window where the cluster exists with no base backup and
  # PostgresBackupStale legitimately fires, because
  # cnpg_collector_last_available_backup_timestamp exports 0 rather than being
  # omitted. Fires only on this resource's FIRST reconcile - adding it to an
  # existing ScheduledBackup does nothing; the resource must be recreated.
  immediate: true
  cluster:
    name: ev-pg
```

`packages/tesla/src/oauth.ts`:

```ts
const TOKEN_URL = 'https://fleet-auth.prd.vn.cloud.tesla.com/oauth2/v3/token'

export interface TokenSet { accessToken: string; refreshToken: string; expiresAt: Date }

export async function exchangeCode(
  code: string, clientId: string, clientSecret: string, redirectUri: string,
): Promise<TokenSet> {
  return post({ grant_type: 'authorization_code', client_id: clientId,
                client_secret: clientSecret, code, redirect_uri: redirectUri, audience: FLEET_AUDIENCE })
}

export async function refresh(
  refreshToken: string, clientId: string,
): Promise<TokenSet> {
  return post({ grant_type: 'refresh_token', client_id: clientId, refresh_token: refreshToken })
}

const FLEET_AUDIENCE = 'https://fleet-api.prd.na.vn.cloud.tesla.com'

async function post(body: Record<string, string>): Promise<TokenSet> {
  const res = await fetch(TOKEN_URL, {
    method: 'POST',
    headers: { 'content-type': 'application/x-www-form-urlencoded' },
    body: new URLSearchParams(body),
  })
  if (!res.ok) throw new Error(`token request failed: ${res.status} ${await res.text()}`)
  const j = await res.json() as { access_token: string; refresh_token: string; expires_in: number }
  return {
    accessToken: j.access_token,
    refreshToken: j.refresh_token,
    expiresAt: new Date(Date.now() + j.expires_in * 1000),
  }
}
```

`packages/tesla/src/fleet-api.ts` wraps exactly three calls and no more — `listVehicles()`, `fleetStatus(vins)` and `getTelemetryConfig(vin)`. **It must not expose a `vehicleData()` helper.** Omitting it is the enforcement mechanism for the global constraint against polling: an endpoint with no wrapper is an endpoint nobody calls by accident.

```ts
const BASE = 'https://fleet-api.prd.na.vn.cloud.tesla.com/api/1'

async function get<T>(path: string, accessToken: string): Promise<T> {
  const res = await fetch(`${BASE}${path}`, {
    headers: { authorization: `Bearer ${accessToken}` },
  })
  if (!res.ok) throw new Error(`${path} failed: ${res.status} ${await res.text()}`)
  return (await res.json() as { response: T }).response
}

export const listVehicles = (t: string) =>
  get<{ vin: string; display_name: string }[]>('/vehicles', t)

export const fleetStatus = (t: string, vins: string[]) =>
  post<{ key_paired_vins: string[] }>('/vehicles/fleet_status', t, { vins })

export const getTelemetryConfig = (t: string, vin: string) =>
  get<{ synced: boolean }>(`/vehicles/${vin}/fleet_telemetry_config`, t)

async function post<T>(path: string, accessToken: string, body: unknown): Promise<T> {
  const res = await fetch(`${BASE}${path}`, {
    method: 'POST',
    headers: { authorization: `Bearer ${accessToken}`, 'content-type': 'application/json' },
    body: JSON.stringify(body),
  })
  if (!res.ok) throw new Error(`${path} failed: ${res.status} ${await res.text()}`)
  return (await res.json() as { response: T }).response
}
```

`packages/db/src/pool.ts`:

```ts
import pg from 'pg'

let pool: pg.Pool | undefined

/**
 * Builds the pool from the discrete PG* variables that CloudNativePG's
 * generated `ev-pg-app` Secret provides. We use the individual fields rather
 * than the `uri` key because the URI form is awkward to override per-consumer.
 */
export function getPool(): pg.Pool {
  if (!pool) {
    pool = new pg.Pool({
      host: required('PGHOST'),
      port: Number(process.env['PGPORT'] ?? 5432),
      user: required('PGUSER'),
      password: required('PGPASSWORD'),
      database: required('PGDATABASE'),
      max: Number(process.env['PGPOOL_MAX'] ?? 10),
      idleTimeoutMillis: 30_000,
    })
  }
  return pool
}

export async function closePool(): Promise<void> {
  await pool?.end()
  pool = undefined
}

function required(name: string): string {
  const v = process.env[name]
  if (!v) throw new Error(`missing required environment variable ${name}`)
  return v
}
```

- [ ] **Step 4: Write the partition-management migration**

`packages/db/migrations/002_partitions.sql` creates a function that ensures the current and next month's partitions exist for both `raw_message` and `sample`, plus partitions covering the current month. The ingest worker calls this function on startup and on the first write of each day, so partitions never need manual creation.

```sql
-- Up

CREATE OR REPLACE FUNCTION ensure_month_partitions(target DATE)
RETURNS void LANGUAGE plpgsql AS $$
DECLARE
  t   TEXT;
  lo  DATE := date_trunc('month', target)::date;
  hi  DATE := (date_trunc('month', target) + INTERVAL '1 month')::date;
  nm  TEXT;
BEGIN
  FOREACH t IN ARRAY ARRAY['raw_message', 'sample'] LOOP
    nm := format('%s_%s', t, to_char(lo, 'YYYY_MM'));
    IF to_regclass(nm) IS NULL THEN
      EXECUTE format(
        'CREATE TABLE %I PARTITION OF %I FOR VALUES FROM (%L) TO (%L)',
        nm, t, lo, hi);
    END IF;
  END LOOP;
END $$;

SELECT ensure_month_partitions(CURRENT_DATE);
SELECT ensure_month_partitions((CURRENT_DATE + INTERVAL '1 month')::date);

-- Down

DROP FUNCTION IF EXISTS ensure_month_partitions(DATE);
```

```ts
import { fileURLToPath } from 'node:url'
import path from 'node:path'
import migrate from 'node-pg-migrate'
import { getPool } from './pool.js'

const migrationsDir = path.join(
  path.dirname(fileURLToPath(import.meta.url)), '..', 'migrations')

export async function runMigrations(): Promise<void> {
  const client = await getPool().connect()
  try {
    await migrate({
      dbClient: client,
      dir: migrationsDir,
      direction: 'up',
      migrationsTable: 'pgmigrations',
      log: (m) => console.log(m),
    })
  } finally {
    client.release()
  }
}

  runMigrations()
    .then(() => process.exit(0))
    .catch((e) => { console.error(e); process.exit(1) })
}
```

```ts
import { makeSample, type ChargeState, type PowerState, type RawMessage, type VehicleSample } from '@ev/core'

type Mutable = Partial<Omit<VehicleSample, 'vehicleId' | 'ts'>>

/**
 * Tesla field name -> how it lands in a VehicleSample.
 * Unknown keys are ignored on purpose: Tesla adds fields, and an unrecognised
 * one must never cost us the rest of the message.
 */
export const TESLA_FIELD_MAP: Record<string, (v: unknown, into: Mutable) => void> = {
  Soc:                 (v, o) => { o.socPct = num(v) },
  RatedRange:          (v, o) => { o.rangeKm = num(v) },
  Odometer:            (v, o) => { o.odometerKm = num(v) },
  VehicleSpeed:        (v, o) => { o.speedKph = num(v) },
  InsideTemp:          (v, o) => { o.insideTempC = num(v) },
  OutsideTemp:         (v, o) => { o.outsideTempC = num(v) },
  ChargerPower:        (v, o) => { o.chargePowerKw = num(v) },
  ACChargingEnergyIn:  (v, o) => { o.chargeEnergyAddedKwh = num(v) },
  DCChargingEnergyIn:  (v, o) => { o.chargeEnergyAddedKwh = num(v) },
  Locked:              (v, o) => { o.locked = bool(v) },
  Location:            (v, o) => {
    const loc = (v as { locationValue?: { latitude?: number; longitude?: number } })?.locationValue
    if (loc) { o.lat = loc.latitude ?? null; o.lon = loc.longitude ?? null }
  },
  ChargeState:         (v, o) => { o.chargeState = chargeState(str(v)) },
  DoorState:           (v, o) => { o.doorsOpen = anyDoorOpen(v) },
}

export function normaliseTeslaMessage(raw: RawMessage): VehicleSample[] {
  const p = raw.payload as { createdAt?: string; data?: { key?: string; value?: unknown }[] }
  const data = p?.data
  if (!Array.isArray(data) || data.length === 0) return []

  const into: Mutable = {}
  let recognised = 0
  for (const entry of data) {
    const key = entry?.key
    if (!key) continue
    const apply = TESLA_FIELD_MAP[key]
    if (!apply) continue
    apply(entry.value, into)
    recognised++
  }
  if (recognised === 0) return []

  const ts = p.createdAt ? new Date(p.createdAt) : raw.receivedAt
  return [makeSample({ vehicleId: raw.vehicleId, ts, ...into })]
}

function num(v: unknown): number | null {
  const o = v as Record<string, unknown>
  for (const k of ['doubleValue', 'floatValue', 'intValue', 'longValue']) {
    const n = o?.[k]
    if (typeof n === 'number') return n
    if (typeof n === 'string' && n.trim() !== '' && !Number.isNaN(Number(n))) return Number(n)
  }
  return null
}

function str(v: unknown): string | null {
  const s = (v as { stringValue?: unknown })?.stringValue
  return typeof s === 'string' ? s : null
}

function bool(v: unknown): boolean | null {
  const b = (v as { booleanValue?: unknown })?.booleanValue
  return typeof b === 'boolean' ? b : null
}

function chargeState(s: string | null): ChargeState | null {
  switch (s) {
    case 'Charging':      return 'charging'
    case 'Complete':      return 'complete'
    case 'Stopped':       return 'stopped'
    case 'Disconnected':  return 'disconnected'
    case 'NoPower':
    case 'Starting':
    case 'Connected':     return 'connected'
    default:              return null
  }
}

function anyDoorOpen(v: unknown): boolean | null {
  const d = (v as { doorValue?: Record<string, boolean> })?.doorValue
  if (!d) return null
  return Object.values(d).some(Boolean)
}
```

`packages/core/src/engine/segmenter.ts`:

```ts
import type { SessionKind, VehicleSample } from '../model.js'

export interface SegmenterOptions {
  /** Stationary for at least this long ends a drive. Long enough to survive a
   *  traffic light, short enough that a shop stop is its own drive. */
  driveEndParkedMs: number
  /** A charge that stops and resumes within this window is one session. */
  chargeResumeWindowMs: number
  /** A gap larger than this means we lost coverage; close whatever is open
   *  rather than inventing a session that spans the hole. */
  sampleGapResetMs: number
  /** Below this the car is stationary. Not zero: GPS speed jitters. */
  movingSpeedKph: number
}

export const DEFAULT_SEGMENTER_OPTIONS: SegmenterOptions = {
  driveEndParkedMs: 5 * 60_000,
  chargeResumeWindowMs: 10 * 60_000,
  sampleGapResetMs: 60 * 60_000,
  movingSpeedKph: 1,
}

export interface OpenSession {
  kind: SessionKind
  startedAt: Date
  startSample: VehicleSample
  lastSample: VehicleSample
  /** When the car first went stationary during a drive; null while moving. */
  stationarySince: Date | null
  /** When charging last stopped, for the resume window. */
  pausedSince: Date | null
}

export interface SegmenterState {
  open: OpenSession | null
  lastTs: Date | null
}

export type SegmenterEvent =
  | { type: 'session-start'; kind: SessionKind; at: Date; sample: VehicleSample }
  | { type: 'session-point'; sample: VehicleSample }
  | { type: 'session-end'; kind: SessionKind; at: Date; sample: VehicleSample }

export interface StepResult {
  state: SegmenterState
  events: SegmenterEvent[]
}

export function initialState(): SegmenterState {
  return { open: null, lastTs: null }
}

export function step(
  state: SegmenterState,
  sample: VehicleSample,
  opts: SegmenterOptions = DEFAULT_SEGMENTER_OPTIONS,
): StepResult {
  // Out-of-order delivery is normal after the car replays its buffer. Dropping
  // is correct: the segmenter is a forward-only state machine, and reprocessing
  // from raw_message is how history gets rebuilt if ordering matters.
  if (state.lastTs && sample.ts.getTime() < state.lastTs.getTime()) {
    return { state, events: [] }
  }

  const events: SegmenterEvent[] = []
  let open = state.open

  const gapMs = state.lastTs ? sample.ts.getTime() - state.lastTs.getTime() : 0
  if (open && gapMs > opts.sampleGapResetMs) {
    events.push({ type: 'session-end', kind: open.kind, at: open.lastSample.ts, sample: open.lastSample })
    open = null
  }

  const isCharging = sample.chargeState === 'charging'
  const isMoving = (sample.speedKph ?? 0) > opts.movingSpeedKph

  if (open?.kind === 'charge') {
    // How long charging has been paused, measured to THIS sample. Evaluated on
    // both branches: a pause that ends the session is just as likely to be
    // discovered when charging resumes as while it is still stopped, because
    // nothing obliges the car to send samples while it sits idle on a charger.
    const pausedFor = open.pausedSince
      ? sample.ts.getTime() - open.pausedSince.getTime()
      : 0
    const terminal =
      sample.chargeState === 'disconnected' || sample.chargeState === 'complete'

    if (isCharging) {
      if (pausedFor >= opts.chargeResumeWindowMs) {
        // Resumed too late to be the same session. Close the old one at its
        // last real sample, and fall through to open a fresh one below.
        events.push({ type: 'session-end', kind: 'charge', at: open.lastSample.ts, sample: open.lastSample })
        open = null
      } else {
        open = { ...open, lastSample: sample, pausedSince: null }
        events.push({ type: 'session-point', sample })
      }
    } else if (terminal || pausedFor >= opts.chargeResumeWindowMs) {
      events.push({ type: 'session-end', kind: 'charge', at: sample.ts, sample })
      open = null
    } else {
      open = { ...open, lastSample: sample, pausedSince: open.pausedSince ?? sample.ts }
    }
  } else if (open?.kind === 'drive') {
    if (isCharging) {
      events.push({ type: 'session-end', kind: 'drive', at: sample.ts, sample })
      open = null
    } else if (isMoving) {
      open = { ...open, lastSample: sample, stationarySince: null }
      events.push({ type: 'session-point', sample })
    } else {
      const stationarySince = open.stationarySince ?? sample.ts
      const stoppedMs = sample.ts.getTime() - stationarySince.getTime()
      if (stoppedMs >= opts.driveEndParkedMs) {
        events.push({ type: 'session-end', kind: 'drive', at: open.lastSample.ts, sample: open.lastSample })
        open = null
      } else {
        open = { ...open, lastSample: sample, stationarySince }
        events.push({ type: 'session-point', sample })
      }
    }
  }

  if (!open) {
    if (isCharging) {
      open = openSession('charge', sample)
      events.push({ type: 'session-start', kind: 'charge', at: sample.ts, sample })
      events.push({ type: 'session-point', sample })
    } else if (isMoving) {
      open = openSession('drive', sample)
      events.push({ type: 'session-start', kind: 'drive', at: sample.ts, sample })
      events.push({ type: 'session-point', sample })
    }
  }

  return { state: { open, lastTs: sample.ts }, events }
}

function openSession(kind: SessionKind, sample: VehicleSample): OpenSession {
  return {
    kind,
    startedAt: sample.ts,
    startSample: sample,
    lastSample: sample,
    stationarySince: null,
    pausedSince: null,
  }
}
```

Idle sessions are deliberately not emitted here. An idle is the absence of a drive or charge and is derived in Task 11 from the gaps between sessions rather than tracked as a third state — one fewer state machine to get wrong.

```ts
import type { SessionKind, VehicleSample } from '../model.js'

export interface MetricsOptions {
  /** Nameplate usable capacity, used to convert SoC delta into energy for
   *  drives. Charges use the car's own energy counter instead, which is
   *  measured rather than inferred. */
  usableCapacityKwh: number
}

export interface SessionSummary {
  startedAt: Date | null
  endedAt: Date | null
  distanceKm: number | null
  energyKwh: number | null
  efficiencyWhPerKm: number | null
  avgSpeedKph: number | null
  maxChargePowerKw: number | null
  startSocPct: number | null
  endSocPct: number | null
  startOdometerKm: number | null
  endOdometerKm: number | null
  startLat: number | null
  startLon: number | null
  endLat: number | null
  endLon: number | null
}

export function summariseSession(
  kind: SessionKind,
  points: VehicleSample[],
  opts: MetricsOptions,
): SessionSummary {
  const first = points[0] ?? null
  const last = points[points.length - 1] ?? null

  const startOdo = firstOf(points, (s) => s.odometerKm)
  const endOdo = lastOf(points, (s) => s.odometerKm)
  const startSoc = firstOf(points, (s) => s.socPct)
  const endSoc = lastOf(points, (s) => s.socPct)

  const distanceKm =
    startOdo !== null && endOdo !== null ? round(endOdo - startOdo, 3) : null

  let energyKwh: number | null = null
  if (kind === 'charge') {
    const added = lastOf(points, (s) => s.chargeEnergyAddedKwh)
    const startAdded = firstOf(points, (s) => s.chargeEnergyAddedKwh) ?? 0
    energyKwh = added !== null ? round(added - startAdded, 3) : null
  } else if (startSoc !== null && endSoc !== null) {
    energyKwh = round(((startSoc - endSoc) / 100) * opts.usableCapacityKwh, 3)
  }

  const efficiencyWhPerKm =
    distanceKm !== null && distanceKm > 0 && energyKwh !== null
      ? round((energyKwh * 1000) / distanceKm, 1)
      : null

  const durationH =
    first && last ? (last.ts.getTime() - first.ts.getTime()) / 3_600_000 : 0
  const avgSpeedKph =
    distanceKm !== null && durationH > 0 ? round(distanceKm / durationH, 1) : null

  const powers = points.map((s) => s.chargePowerKw).filter(isNum)

  return {
    startedAt: first?.ts ?? null,
    endedAt: last?.ts ?? null,
    distanceKm,
    energyKwh,
    efficiencyWhPerKm,
    avgSpeedKph,
    maxChargePowerKw: powers.length ? Math.max(...powers) : null,
    startSocPct: startSoc,
    endSocPct: endSoc,
    startOdometerKm: startOdo,
    endOdometerKm: endOdo,
    startLat: firstOf(points, (s) => s.lat),
    startLon: firstOf(points, (s) => s.lon),
    endLat: lastOf(points, (s) => s.lat),
    endLon: lastOf(points, (s) => s.lon),
  }
}

export interface IdleSpan { startedAt: Date; endedAt: Date }
export interface IdleOptions { minIdleMs: number }

/**
 * An idle is the absence of a drive or charge, derived from the gaps between
 * them rather than tracked as its own state. One fewer state machine to get
 * wrong, and it cannot disagree with the sessions it sits between.
 */
export function deriveIdles(
  sessions: { startedAt: Date; endedAt: Date | null }[],
  opts: IdleOptions,
): IdleSpan[] {
  const ordered = [...sessions]
    .filter((s) => s.endedAt !== null)
    .sort((a, b) => a.startedAt.getTime() - b.startedAt.getTime())

  const out: IdleSpan[] = []
  for (let i = 0; i < ordered.length - 1; i++) {
    const end = ordered[i]?.endedAt
    const next = ordered[i + 1]?.startedAt
    if (!end || !next) continue
    if (next.getTime() - end.getTime() >= opts.minIdleMs) {
      out.push({ startedAt: end, endedAt: next })
    }
  }
  return out
}

function isNum(v: number | null): v is number { return v !== null }

function firstOf(points: VehicleSample[], pick: (s: VehicleSample) => number | null): number | null {
  for (const p of points) { const v = pick(p); if (v !== null) return v }
  return null
}

function lastOf(points: VehicleSample[], pick: (s: VehicleSample) => number | null): number | null {
  for (let i = points.length - 1; i >= 0; i--) {
    const p = points[i]
    if (!p) continue
    const v = pick(p)
    if (v !== null) return v
  }
  return null
}

function round(n: number, dp: number): number {
  const f = 10 ** dp
  return Math.round(n * f) / f
}
```

```ts
export interface CapacityInput {
  startSocPct: number | null
  endSocPct: number | null
  energyKwh: number | null
}

export interface CapacityEstimate {
  estimatedCapacityKwh: number
  confidence: number
}

/** Charges narrower than this tell you almost nothing: measurement error in
 *  SoC swamps the signal. */
const MIN_SOC_SPAN = 20

export function estimateCapacity(c: CapacityInput): CapacityEstimate | null {
  const { startSocPct, endSocPct, energyKwh } = c
  if (startSocPct === null || endSocPct === null || energyKwh === null) return null

  const span = endSocPct - startSocPct
  if (span < MIN_SOC_SPAN || energyKwh <= 0) return null

  return {
    estimatedCapacityKwh: round(energyKwh / (span / 100), 2),
    // Confidence scales with span: a 20% charge is the floor, 80% or more is
    // as good as this method gets.
    confidence: round(Math.min(1, span / 80), 3),
  }
}

function round(n: number, dp: number): number {
  const f = 10 ** dp
  return Math.round(n * f) / f
}
```

```ts
import {
  initialState, normaliseIfKnown, step, summariseSession,
  type MetricsOptions, type RawMessage, type SegmenterState,
  type SessionKind, type SessionSummary, type VehicleSample,
} from './deps.js'

/**
 * The pipeline's view of persistence. Argument order here is deliberately
 * (kind, vehicleId, at) rather than the repo layer's (client, vehicleId, kind,
 * startedAt): main.ts adapts between them by binding a PoolClient, which is
 * also what keeps the pipeline free of any pg types and therefore unit-testable
 * with the plain fake in the test above.
 */
export interface Store {
  insertRaw(m: RawMessage): Promise<void>
  insertSample(s: VehicleSample): Promise<void>
  openSession(kind: SessionKind, vehicleId: string, at: Date): Promise<string>
  appendPoint(sessionId: string, s: VehicleSample): Promise<void>
  closeSession(sessionId: string, summary: SessionSummary): Promise<void>
}

export class Pipeline {
  private state: SegmenterState = initialState()
  private openId: string | null = null
  private openPoints: VehicleSample[] = []

  constructor(private store: Store, private opts: MetricsOptions) {}

  /** Raw first, always. The tape is what makes everything else rebuildable,
   *  so a crash between the two writes must never lose the message. */
  async handle(raw: RawMessage): Promise<void> {
    await this.store.insertRaw(raw)
    for (const sample of normaliseIfKnown(raw)) {
      await this.handleSample(sample)
    }
  }

  async handleSample(sample: VehicleSample): Promise<void> {
    await this.store.insertSample(sample)
    const { state, events } = step(this.state, sample)
    this.state = state

    for (const e of events) {
      if (e.type === 'session-start') {
        this.openId = await this.store.openSession(e.kind, sample.vehicleId, e.at)
        this.openPoints = []
      } else if (e.type === 'session-point' && this.openId) {
        this.openPoints.push(e.sample)
        await this.store.appendPoint(this.openId, e.sample)
      } else if (e.type === 'session-end' && this.openId) {
        const summary = summariseSession(e.kind, this.openPoints, this.opts)
        await this.store.closeSession(this.openId, summary)
        this.openId = null
        this.openPoints = []
      }
    }
  }
}
```

```ts
  }
```

- [ ] **Step 5: Write the MQTT consumer and entrypoint**

`apps/ingest/src/mqtt.ts` connects with `clean: false` and a fixed `clientId`, subscribes at QoS 1, and — critically — **does not auto-acknowledge**. Use `mqtt.js` with `manualConnect` and handle each message inside an async queue so that an unhandled message is not acked. The durability chain in the spec depends on this: acking before the row is committed converts a worker crash into silent data loss.

```ts
import mqtt from 'mqtt'
import type { RawMessage } from '@ev/core'

export interface MqttOptions {
  url: string; username: string; password: string
  clientId: string; topic: string; vehicleId: string
}

export function subscribe(
  opts: MqttOptions, onMessage: (m: RawMessage) => Promise<void>,
): mqtt.MqttClient {
  const client = mqtt.connect(opts.url, {
    clientId: opts.clientId,
    username: opts.username,
    password: opts.password,
    clean: false,          // durable session: the broker holds our backlog
    reconnectPeriod: 2000,
    manualConnect: false,
  })

  client.on('connect', () => { client.subscribe(opts.topic, { qos: 1 }) })

  client.handleMessage = (packet, done) => {
    const payload = JSON.parse((packet as { payload: Buffer }).payload.toString())
    onMessage({
      vehicleId: opts.vehicleId,
      vendor: 'tesla',
      receivedAt: new Date(),
      source: 'telemetry',
      payload,
    }).then(() => done(), (err) => { console.error('handler failed', err); done(err as Error) })
  }

  return client
}
```

Overriding `handleMessage` rather than listening on `'message'` is what defers the QoS 1 acknowledgement until `done()` is called. An `'message'` listener acks immediately and would break the guarantee.

`apps/web/src/lib/server/session.ts`:

```ts
import { SignJWT, jwtVerify } from 'jose'

export interface SessionUser { sub: string }

/**
 * Exactly one Pocket-ID subject may use this application. Authenticating
 * successfully against the IdP is necessary but not sufficient: the SSO
 * instance serves other applications and other people.
 */
export function isAuthorisedSubject(sub: string, allowed: string): boolean {
  return allowed.length > 0 && sub === allowed
}

export async function sealSession(u: SessionUser, key: string): Promise<string> {
  return new SignJWT({ sub: u.sub })
    .setProtectedHeader({ alg: 'HS256' })
    .setIssuedAt()
    .setExpirationTime('30d')
    .sign(new TextEncoder().encode(key))
}

export async function unsealSession(token: string, key: string): Promise<SessionUser | null> {
  try {
    const { payload } = await jwtVerify(token, new TextEncoder().encode(key))
    return typeof payload.sub === 'string' ? { sub: payload.sub } : null
  } catch {
    return null
  }
}
```

`apps/web/src/hooks.server.ts`:

```ts
import type { Handle } from '@sveltejs/kit'
import { unsealSession } from '$lib/server/session.js'
import { env } from '$env/dynamic/private'

const PUBLIC_PATHS = [
  '/auth/login', '/auth/callback',
  '/healthz/live', '/healthz/ready',
  '/.well-known/',                 // Tesla fetches this unauthenticated
]

export const handle: Handle = async ({ event, resolve }) => {
  const token = event.cookies.get('ev_session')
  event.locals.user = token ? await unsealSession(token, env.SESSION_KEY) : null

  // Bearer tokens are accepted so a native app can use the same API later
  // without reshaping routes. Nothing issues one yet; the branch exists so the
  // route handlers never need to change when something does.
  if (!event.locals.user) {
    const bearer = event.request.headers.get('authorization')?.replace(/^Bearer /, '')
    if (bearer) event.locals.user = await unsealSession(bearer, env.SESSION_KEY)
  }

  const path = event.url.pathname
  const isPublic = PUBLIC_PATHS.some((p) => path === p || path.startsWith(p))

  if (!isPublic && !event.locals.user) {
    if (path.startsWith('/api/')) return new Response('unauthorized', { status: 401 })
    return new Response(null, { status: 302, headers: { location: '/auth/login' } })
  }

  return resolve(event)
}
```
